System design showcase

Fashion E-Commerce Platform

A microservices backend for an Indian streetwear brand: 10 NestJS services behind one API gateway, on PostgreSQL and Redis, in an Nx monorepo. The foundation, the authentication service, the gateway, the catalog pair and the image service are built and tested. The order, payment and notification services are designed and next.

The source code is private. These pages show the architecture and design.

Build status

P1 · done

Engineering highlights

Authentication

  • Refresh-token rotation with reuse detection in one atomic Redis Lua script
  • Google sign-in with PKCE and a per-sign-in state cookie
  • Login throttling per number and per IP, with constant-time failures

API gateway

  • Path normalisation that refuses encoded attempts to reach internal routes
  • Per-IP and per-user rate limits in Redis that fail open
  • Request bodies streamed untouched, so webhooks arrive byte for byte

Catalog, split read from write

  • catalog-command owns the writes; catalog-query owns reads, search and the cache
  • A write publishes on catalog:invalidate; the subscriber handles each message twice, 5 s apart
  • Reservation keys on the inventory ledger make a repeated stock reservation safe

Images

  • files-service converts every upload to WebP with Sharp and stores it in Cloudflare R2
  • It publishes its own cache bust, so a new image shows up without a catalog write
  • A publish locks the product row, so it cannot race the delete of a last image

Data and delivery

  • 45 CHECK constraints and 26 unique indexes for money in paise, stock and returns
  • CI with Postgres and Redis containers and a migration-drift check
  • 10 service design docs and 3 architecture decision records

Service boundaries

  • Services trust identity headers only with the gateway's secret, checked by a shared guard
  • Internal routes answer 404 for anything arriving from outside
  • Nx module boundaries are enforced in CI, so a service cannot import another's internals
